# うまくいかないとき

| 起きたこと | すること |
|---|---|
| ポータルの招待メールが届かない | 迷惑メールのフォルダを見る。無ければ会場の担当者に知らせる |
| SD-WAN Manager で証明書の警告が出る | 自己署名の証明書です。ブラウザの「詳細設定」から先に進む |
| SD-WAN Manager にログインできない | パスワードを変えずに、会場の担当者に知らせる（共有の利用者なので、ほかの人が変えた可能性もある） |
| ツアーに「前提のツアーが未クリア」と出る | ツアーの画面に出る前提のツアーを先にクリアする（[アジェンダ](02_agenda.md)） |
| live の確認が「まだ確認できません」 | 実機がまだ期待した状態になっていない、という判定。数分待って押し直す。SSE-02 は直近 15 分のログを見るので、古ければ席の Edge で `http://exampleadultsite.com` を開き直してから押す |
| 「まだ確認できません」が 2 回続いた | 「できた（自己申告）」のボタンが出る。画面で確認することを見ていれば、それを押して進む。見ていなければ、手順をやり直してから押す |
| live の確認が「確認できませんでした」 | 製品の API に問い合わせられなかった状態。画面で確認することを見ていれば、自己申告に切り替えて進む。進行は止めない |
| メニューの名前がガイドと違う | ポータルの手順の文を正とする。見つからなければ会場の担当者に知らせる |
| 保存やデプロイのボタンが押せそうに見える | 押さずに止めて、会場の担当者に知らせる |
| BASE-04 のトレースが一覧に無い | 会場の担当者に知らせる。担当者がいないときは、説明と表を読んで進める |
| 「いま空いている席がありません」 | しばらくしてから「席をもらう」を押し直す |
| 「あなたの席」に「まだ用意していません」 | 会場の担当者に知らせる |
| Duo のあとに「Access Denied」 | 自分の席の URL と Duo の利用者の組み合わせかを確かめる。正しくても出るときは、数分待ってから入り直し、続くなら担当者に知らせる |
| Duo で「Invalid credentials」 | パスワードを手で打ち直す。続くなら担当者に知らせる（体験会の外では席の利用者は止めてある） |
| 席の画面が切れた | 1 回のセッションは最長 30 分。「席の URL を開く」から入り直す |
| 席でキーボードの記号がずれる | 配列は English (US) です。パスワードは英字と数字だけなので、そのまま打てる |
| SSE-02 で止めるサイトが開けてしまう | 手元のブラウザで開いていないかを確かめる。席の Edge で開き直す |
| SSE-02 の HTTPS でページが開かない（`ERR_TIMED_OUT`） | 正しい動き。CSA は HTTPS を復号しないので、止めてもブロック画面を出せない |
| SSE-06 の GUEST の席で「接続がプライベートではありません」 | 正しい動き。アドレスが `block.sse.cisco.com/swg` なら CSA で止まっている。席に CSA のルート証明書を入れていないので警告になる |
| SSE-06 で GUEST の席に入れない | Duo は CORP の席と同じ利用者、Windows は「GUEST の席」に出ている利用者かを確かめる |
| 席で Duo の画面に前の利用者名が出ている | 「編集」で、ポータルの「あなたの席」の Duo の利用者に替える |
